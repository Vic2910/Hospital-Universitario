## Autenticación, autorización y datos

- Se soportan `doctor` → Médico y `patient` → Paciente. Además de la autenticación, se requiere perfil activo y vínculo válido a personal o paciente.
- `my_access` resuelve roles y contexto del servidor. Un solo rol abre su Inicio; con ambos se permite elegir perfil. No se confía en roles elegidos libremente ni en `user_metadata` para autorizar.
- La contraseña no se almacena en la app. El acceso vive en memoria y la renovación en Keychain para iOS o `sessionStorage` para web. El cierre utiliza `scope=local` y descarta las credenciales locales incluso si falla la confirmación remota.
- La app permite desafiar/verificar un TOTP previamente inscrito. No incluye inscripción/eliminación de factores ni SMS.
- `my_profile` obtiene datos propios. `my_activity_summary` proporciona los contadores autorizados; si requiere MFA se muestra un aviso y no se inventan cifras.
- Habitaciones se consulta con `read_resource('rooms')`. `active` no significa cama libre: ocupación y doble asignación siguen controladas en el servidor.
- Los turnos del médico son `staff_shifts`, con filtro por personal y semana local de lunes a lunes, orden por intervalo y cursor estable durante la paginación.
- El turno del paciente es `queue_tickets`. `my_queue_status` devuelve número visible, personas anteriores, turno atendido y consultorio autorizado. No se cuentan identidades ajenas en el cliente ni se inventa una espera estimada. La pantalla activa se actualiza cada 30 segundos y al volver a primer plano.
- `hospital_overview` ofrece ocupación agregada, médicos de turno y avisos públicos.

No se recreó el esquema ni se aplicaron nuevas migraciones en esta sesión. Se reutilizaron las funciones, restricciones y RLS existentes.

## Vista previa web en Windows

Archivos en `web-preview/`: servidor Node sin dependencias, HTML, CSS, presentación JavaScript, adaptador Auth y ejemplos de diseño.

Desde la raíz, con Node.js 22 o posterior:

```powershell
node --preserve-symlinks --preserve-symlinks-main web-preview/server.mjs
```

Abrir `http://127.0.0.1:4173/`. No se necesita `npm install`. El servidor escucha solo en el equipo local y sirve una lista explícita de recursos con CSP y `no-store`; no expone el repositorio ni `.local/`.

Hay dos modos separados:

- **Login real:** utiliza Supabase y los permisos del servidor.
- **Diseño:** botones Médico/Paciente fuera del iPhone, con ejemplos locales de `design-fixtures.json`. Permite recorrer las 21 pantallas sin credenciales ni llamadas a Supabase. No crea registros ni concede una sesión real. Los guardados permanecen deshabilitados.

La superficie interior de referencia es 393 × 852 cuando hay espacio. La web adapta la altura y el ancho; no ejecuta el simulador ni SwiftUI. Las reglas y modelos se comparten mediante el núcleo JavaScript y los contratos, mientras cada plataforma tiene su transporte, almacenamiento y presentación.
